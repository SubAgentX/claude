Project Bootstrap Playbook

Every command needed to go from an empty terminal to a running project with CI, created from your template repository. Pick your machine above and the page shows only the commands that apply to it.

template → github.com/SubAgentX/project-template

Part one

Set up the machine

Run these once per computer. Skip any tool you already have.

1

Install Git

Everything below depends on it. Check with git --version before installing.

macOS
brew install git
Linux · Debian / Ubuntu
sudo apt update && sudo apt install -y git
Windows · PowerShell
winget install --id Git.Git -e

Restart your terminal afterwards. winget updates PATH, but an already-open PowerShell window keeps the old one and will report git as not found.

2

Install the GitHub CLI

This is what creates a repository from your template in one command.

macOS
brew install gh
Linux · Debian / Ubuntu
sudo apt install -y gh
Windows · PowerShell
winget install --id GitHub.cli -e
3

Sign in to GitHub

Choose GitHub.com, then HTTPS, then authenticate in the browser. This also sets up git credentials, so pushes stop asking for a password.

Every platform
gh auth login
4

Set your commit identity

Without this, git refuses your first commit. The name and email appear on every commit you make.

Every platform
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
5

Allow local scripts to run

Windows blocks .ps1 files by default, so init.ps1 would fail with running scripts is disabled on this system. This permits scripts for the current window only and resets when you close it — the safe way to do it.

Windows · PowerShell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

Make it permanent instead? Run Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned once. That allows your own local scripts while still blocking unsigned ones downloaded from the internet.

Part two

Create a project

The sequence you repeat for every new project. Substitute your own name for my-app throughout.

1

Go to where you keep code

Creates the folder if it is not there yet, then moves into it.

macOS
mkdir -p ~/projects && cd ~/projects
Linux
mkdir -p ~/projects && cd ~/projects
Windows · PowerShell
New-Item -ItemType Directory -Force ~\projects | Out-Null
cd ~\projects
2

Create the repository from your template

One command creates a new GitHub repository from the template, gives it a clean first commit with none of the template's history, and clones it locally with the remote already wired up. Swap --private for --public if you want it visible.

Every platform
gh repo create my-app --template SubAgentX/project-template --private --clone
cd my-app
3

Bootstrap the scaffold

Fills in the project name, strips the template instructions out of the README, tidies the placeholder files, creates .env from the example, then deletes itself. The second argument is your new repository, not the template.

macOS
./scripts/init.sh "My App" "SubAgentX/my-app"
Linux
./scripts/init.sh "My App" "SubAgentX/my-app"
Windows · PowerShell
./scripts/init.ps1 "My App" "SubAgentX/my-app"

Run it with no arguments to be prompted for each value instead.

4

Open it in VS Code

If code is not recognised, open VS Code and run Shell Command: Install 'code' command in PATH from the command palette.

Every platform
code .
5

Wire up lint and test

The scaffold ships four stubs that print a reminder and pass. Edit them to call your real tools — the comments at the top of each file list the usual command for Node, Python, Go and Rust.

Keep each pair doing the same thing: CI runs the shell version on Linux and macOS and the PowerShell version on Windows, so a difference shows up as one platform failing.

Files to edit
scripts/lint.sh    scripts/lint.ps1
scripts/test.sh    scripts/test.ps1
6

Check it passes locally

CI runs exactly these scripts, so green here means green there.

macOS
./scripts/lint.sh && ./scripts/test.sh
Linux
./scripts/lint.sh && ./scripts/test.sh
Windows · PowerShell
./scripts/lint.ps1
./scripts/test.ps1
7

Commit and push

This first push is what triggers CI. Watch it under the Actions tab on GitHub — six jobs run, lint and test across Ubuntu, Windows and macOS.

Every platform
git add -A
git commit -m "Set up project from template"
git push
Part three

Starting without a GitHub repository

For a local experiment you are not ready to publish. Needs Node installed for npx, but no gh and no GitHub account.

1

Pull the template with no git history

degit downloads the files only — no .git folder, nothing to clean up afterwards.

Every platform
npx degit SubAgentX/project-template my-app
cd my-app
git init
2

Bootstrap, leaving the repository blank

Pass the name only. The README keeps its <owner>/<repo> placeholders until you decide where it lives.

macOS
./scripts/init.sh "My App"
Linux
./scripts/init.sh "My App"
Windows · PowerShell
./scripts/init.ps1 "My App"
3

Publish it later, when you are ready

Creates the GitHub repository from what you already have locally and pushes in one step.

Every platform
git add -A && git commit -m "Initial commit"
gh repo create my-app --source=. --private --push
Part four

When something goes wrong

The failures worth knowing about before you hit them.

Windows running scripts is disabled on this system

PowerShell's execution policy is blocking init.ps1. Allow scripts for this window only, then run it again.

PowerShell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

Windows the file is not recognised as a command

PowerShell will not run a script from the current folder without a path prefix. Use ./scripts/init.ps1, never a bare scripts/init.ps1.

A .sh file will not run here at all. Use the .ps1 version, or switch the VS Code terminal to Git Bash from the dropdown beside the + in the terminal panel.

Every platform permission denied when running a script

The executable bit did not survive the copy. Restore it and run again.

macOS · Linux
chmod +x scripts/*.sh

Every platform CI passes but the tests actually failed

This one only bites on Windows, and it is silent. PowerShell does not fail a script when a command inside it exits non-zero — it carries on and still reports success, so a broken test suite shows a green build.

The shipped stubs already guard against it on PowerShell 7.3 and newer. On Windows PowerShell 5.1 there is no such setting, so check the exit code yourself after every command you add:

Inside your .ps1 scripts
npm test
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

Every platform gh: command not found

Either the CLI is not installed, or your terminal is still running with the PATH it had before you installed it. Close the terminal, open a new one, and try again before reinstalling.

Every platform the CI matrix costs too much

Six jobs run on every push. That is free on public repositories, but on private ones Windows minutes bill at twice the rate and macOS at ten times. If a project only ever runs in one place, cut the matrix down in .github/workflows/ci.yml:

ci.yml
matrix:
  os: [ubuntu-latest]
